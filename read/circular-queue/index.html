1. 为什么需要循环队列？

假设用长度为 5 的数组顺序保存一个队列。起初不断入队，队尾索引一路向右移动；即使前面的元素已经出队，数组左侧也可能空着。此时如果只允许 rear 增加，就会遇到一个悖论：数组还有空位，队尾却已经触碰边界。

这就是假溢出。问题不在于容量真的耗尽，而在于我们没有重新利用数组开头已经释放的位置。

普通顺序队列前端空闲位置无法自动复用

front → 2 rear → 5（越界）

2. 从直觉到环形模型

把数组最后一个位置想象成紧挨着第一个位置。队尾移动到边界时，它不必继续向右，而是返回索引 0。存储空间没有真的弯成圆环，发生变化的是下标计算规则。

先预测，再看公式

如果容量是 5，当前队尾在索引 4，那么下一个有效索引应该是什么？答案是 0。因为我们希望索引始终落在 0 ～ 4。

3. 取模回绕与判空判满

利用余数运算就能统一表达移动与回绕：

nextIndex = (index + 1) % capacity从任意合法下标前进一步

一个常见的实现策略是刻意保留一个空位置，用两个下标区分空和满：

判空front === rear
判满(rear + 1) % capacity === front

因此，当数组长度是 5 时，这种方案最多保存 4 个元素。其他实现也可以通过额外的计数器充分利用全部容量，但需要同步维护更多状态。

4. C++ 实现示例

下面是用于说明下标规则的简化实现；这是示例代码，正式的运行与编译记录将在后续阶段接入。

circular_queue.cpp · 教学示例#include <vector>
#include <stdexcept>

class CircularQueue {
  std::vector<int> data;
  size_t front = 0, rear = 0;
public:
  explicit CircularQueue(size_t n) : data(n) {
    if (n < 2) throw std::invalid_argument("n must be >= 2");
  }
  bool empty() const { return front == rear; }
  bool full() const { return (rear + 1) % data.size() == front; }
  bool push(int x) {
    if (full()) return false;
    data[rear] = x;
    rear = (rear + 1) % data.size();
    return true;
  }
  bool pop() {
    if (empty()) return false;
    front = (front + 1) % data.size();
    return true;
  }
};
