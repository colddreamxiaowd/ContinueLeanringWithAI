# 可直接复制的调用示例

## 写一篇

> 使用 xiaowd-blog-writing Skill，把以下代码与运行记录整理成一篇中文技术长文。沿用我前几篇文章的讲法：具体问题→为什么→原理→小实验→完整实现→反例→验收。只使用我给出的实测事实，不编造输出。交付独立 Markdown，并检查命令与文件路径。

## 接着写下一篇

> 使用 xiaowd-blog-writing Skill。请先读取当前 GitHub 仓库的 README、上一章教程和相关源码，再写《从零开发 XXX（NN）》。不要重建项目，不要改旧模块接口。附本篇新增文件、Windows CMD 命令、正反向测试、验收清单、局限与下一篇缺口。对于尚未在我的电脑上测试的内容明确写“待本机验收”。

## 一次性写完整系列

> 使用 xiaowd-blog-writing Skill，先按现有源文件建立 04–12 的章节依赖矩阵，再完整写完九篇，而不是只给提纲。每篇独立成文；合订本从单篇自动汇总；源码单一真源；执行代码测试和 Markdown 静态自检后才给下载链接。没有实际验收的能力不得写成“已经运行成功”。

## 质量重写

> 使用 xiaowd-blog-writing Skill，审查这篇文章。先按质量门槛指出实质性缺陷（尤其是原理、反例、代码一致性、真实验收），然后直接重写全文，不要只扩充字数。保留旧章节节奏和真实源码文件名。

## 与 Tutor Skill 配合

> 先使用 tutor-skill 的 Assess→Orient→Guide→Check→Summarize 判断我掌握到哪一步；写成最终博客时再按 xiaowd-blog-writing 的发布规范完成文章、代码、实验与验收。
