# 小知角色视觉逆向核验 · 2026-10-23

## 结论

之前的两个“矢量角色”分别有不同问题：

1. \`xiaozhi-reference.svg\` 是 SVG 容器内嵌 125×164 的 PNG，外观接近参考，但主体**不是可编辑的路径**；
2. \`Xiaozhi.tsx\` 的 \`art="vector"\` 是根据描述手绘多边形，帽沿、脸颊、尾巴、真实色值和眼睛间距不忠实于用户的参考图；
3. 八个 mood 并未获得八份独立面部表情底稿：原参考版只叠加状态贴纸；不能把它宣传成八个完整表情动画；
4. 导航头像直接缩小全身图会失去表情和帽檐细节，必须使用同一份路径的专门头像裁切；小尺寸还应人工审图；
5. 参考截图是 RGB 背景合成图，不含原始 Alpha。背景分离虽能得到视觉保真的路径，但边缘的 Alpha 真值仍需原作者透明母稿才能最终确认。

## 实测证据

- 用户指定的参考截图：573×573 RGB，共 443 种 RGB 颜色；
- 经最大连通的深色/饱和区域、7px 闭运算和最外边界填充，获得角色前景 179,751 像素；
- **真正的角色前景只有 25 种颜色**，没有必要靠 AI 猜测轮廓或添加渐变；
- 前景 bbox: x=83, y=17, 宽=422, 高=538；
- 7,851 条逐行颜色游程，经垂直合并得到 1,579 个矩形；
- 25 个 \`<path>\` 元素（每个颜色一个），没有 \`<image>\`，约 29KiB；
- 按 573×573 的参考网格 rasterize 后，使用 CairoSVG 实测：前景 RGB 失配像素=0，Alpha 掩膜失配=0；
- Inkscape 命令行渲染交叉检查：前景 RGB 失配像素=0，Alpha 掩膜失配=0。透明区域 RGB 可不同但不影响呈现。
- 上述 **零误差仅针对算法提取的前景原尺寸重渲染**，不意味着背景去除无误、缩放无误，也不代表语义编辑能力完整。

## 什么叫真正可编辑？

目前 25 个色板路径，可以使用 Inkscape 节点工具改色和局部像素。它是**路径级可编辑**，不是**部件级或动画骨骼级可编辑**。眼睛、嘴巴、帽子、前后肢、尾巴尚未建立独立可交换且统一描边的语义组。不能因 SVG 通过像素 diff 就声称能做像素级一致的眨眼或走路。

建议下一步只制作真正的语义层：
\`hat\`、\`tassel\`、\`ear-left/right\`、\`eye-left/right\`、\`mouth\`、\`blush-left/right\`、\`body\`、\`tail\`。
**静态姿态**必须将这些层合成为同一份母稿的外观；**动画帧**另设可接受的局部变化和逐帧验收。

## 专业工具方案

- [Inkscape](https://inkscape.org)：针对结果做像素网格节点审查、分层和逐姿态微调；
- [VTracer](https://github.com/visioncortex/vtracer)：\`pixel\` 模式、色彩层级、前后向 A/B 检查；适合通用颜色图像转换；
- [ImageTracerJS](https://github.com/jankovicsandras/imagetracerjs)：理解调色板量化、路径拟合、直角增强和轮廓处理；
- OpenCV + Pillow + 自定义逐行游程合并：针对已知 25 色图做**更可证伪的逐像素保真**。

矢量图完整性验收分三个级别：

1. **A — 原尺寸前景保真**：对照像素值与透明 mask（当前算法得到 0 错误）。
2. **B — 产品尺寸可用**：24/32/48/96/160px 头像与角色尺寸，检查眼睛是否合并、帽檐是否断裂、背景是否漏色。
3. **C — 动画和结构保真**：分组后的静态帧与母稿一致，并在每次状态切换时仅改变授权部位。

目前只完成 A，B 已做初步观察但未人工签收，C 未完成。
