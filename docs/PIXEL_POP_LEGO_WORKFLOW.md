# Pixel Pop — 搭积木式视觉开发（LEGO Workflow）

当前官方视觉基准：用户确认的**黄色新粗野主义首页**（1448×1086），其品牌 DNA 固定为 65% 新粗野主义、25% 像素学院、10% 安静的学习留白。

## 工作方式

每批**最多三个可独立渲染的零件**，每块具备明确的 props、局部样式和演示数据。
先完成独立展示，再和基准设计图对照，再进入下一批，最后集中集成页面。
**禁止为了还原一个局部组件去覆盖整站 CSS，禁止以 CI 通过代替视觉验收。**

1. **拆图：** 从最终参考图标注可被独立测试的区域、尺寸、固定视觉细节及可替换内容。
2. **封装：** 一块组件一个责任，使用 CSS Module + 原有 Token 和唯一 PixelCat 吉祥物，不混合课程进度数据。
3. **独立预览：** 放在 \`/ui-lab/blocks\`，要能被单独放大查看，避免整页信息干扰判断。
4. **截图对照：** 桌面 1440×900（主基准也可按原图 1448×1086）、平板 768px、手机 390px；从真实浏览器截图，而不是模型生成概念图。
5. **验收：** 逐项核对几何比例、字体层级、黑色粗描边、硬阴影、颜色、装饰数量、点击与焦点，以及溢出风险；记录偏差并迭代当前块。
6. **整合：** 零件通过之后替换原有页面的一小部分，保证 CoursePack/飞书源数据和学习进度契约不变化；同时回归验证三个 UI 密度模式。

## 移交给其他模型的指令

> 你正在执行知序 Pixel Pop 的 LEGO 视觉还原。
> 必读 docs/PIXEL_POP_DESIGN_SYSTEM.md 与 docs/PIXEL_POP_LEGO_WORKFLOW.md。
> 本次只开发当前批次最多三个组件，优先复用已存在的 TSX/CSS Module 和固定 PixelCat。
> 按已确认参考图真实标注进行独立预览、截图对照和有边界的修正；
> 不要把所有组件混进一个长页面里一次性开发，不要新增另一套配色或设计语言。
> 界面风格为 65% 新粗野主义、25% 像素学院、10% 留白；课程数据仍走 CoursePack。
> 输出可查看的 preview / PR、真实构建测试结果、尚存的视觉偏差、下一批建议。
